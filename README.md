# 助教小莉 · 课程答疑

上海外国语大学贤达经济人文学院《计算思维》课程的答疑助教。
学生把报错粘进去，它给出对应的处理办法。

> **它的知识全部来自课程材料，不是大模型自己想的。匹配不上就说匹配不上。**

---

## 一条设计原则

**判断由规则给出，不由大模型给出。**

报错匹配走确定性的字符串比对。命中就给课程材料里写好的做法，
不命中就直说"这个我没见过"，然后请学生去问老师。

为什么不用大模型来答这一层：**因为它太熟了**。
大模型见过几百万个 `ModuleNotFoundError`，熟到会自信地给你一个
和本课程完全无关的解法——比如让学生去改系统环境变量，而真实原因
只是他没用 PyCharm 打开整个文件夹。

**能用确定规则解决的，不要交给大模型。** 这也是课上讲的内容之一。

---

## 它能做什么

| 标签页 | 做什么 |
|---|---|
| 🚑 报错急救 | 粘贴红字或 `诊断.py` 的输出，匹配出对应的处理办法 |
| 📦 装环境 | Windows / Mac 的安装步骤，含 Mac 专属的坑 |
| 📘 概念速查 | 按知识点查课上讲过的概念 |

**它不会做的事**

- 不告诉你测验题选哪个（知识库里根本没存答案，见下）
- 不替你写作业
- 不回答课程之外的问题


## 知识库怎么来的

`知识库.json` 是**生成物，不要手改**。改源材料，然后重跑：

```bash
python 建知识库.py
```

它读三样东西：

| 源 | 抽出什么 |
|---|---|
| `使用说明.txt` | 通用报错清单 |
| `Mac版安装说明.txt` | Mac 报错清单 + 安装步骤 |
| `计算思维-第N章-题库.docx` | 知识点与解析 |

这样设计的好处：**材料改一处，助教立刻跟着变。**

比如 PyCharm 在 2025 年把 Community 版和 Professional 版合并了，
网上的教程全都过时。我们只要改一次安装说明，助教就不会再教学生
去找早已不存在的 Community Edition——
而一个纯靠大模型的助教，会继续错下去，还会对每个学生各错一次。

---

## ⚠ 一个刻意的限制：知识库里没有测验答案

题库那些题要拿去做测验。如果助教能报答案，学生把题一贴就知道选哪个，
测验就废了。

所以 `建知识库.py` **只抽取「知识点」和「答案解析」，不抽取「答案」那一行**，
并且每次生成后都自动检查一遍有没有泄漏。

助教的定位是：**把道理讲清楚，但不告诉你选哪个。**

---

## 每讲完一章，怎么加内容

1. 把这一章的题库 docx 放进题库目录
2. 在 `建知识库.py` 的 `main()` 里加一行 `jie_tiku(新路径, 章号)`
3. 学生这一章新撞上的报错，补进 `使用说明.txt` 的报错清单
4. `python 建知识库.py`
5. 提交，Streamlit Cloud 自动重新部署

**知识库随课程进度长，不需要重写任何代码。**

## 目录

```
建知识库.py      从课程材料抽取知识库（构建期）
知识库.json      生成物
匹配.py          报错匹配内核，纯规则，零幻觉
app.py           Streamlit 界面
```

`匹配.py` 可以单独跑，会做一遍自检：

```bash
python 匹配.py
```
